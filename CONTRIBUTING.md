# Contributing

Open an issue describing the intended outcome, evidence and scope before substantial changes. For a fix, reproduce the issue with a focused test when practical. Keep changes small and compatible with existing device identities and data.

1. Fork the repository and create a feature branch.
2. Run the build and tests in the README.
3. Document behavior changes, security boundaries, known limitations and migration impact.
4. Submit a pull request with a clear summary and verification evidence.

Do not include credentials, account identifiers, private media or generated artifacts in commits. Do not run tests against a live service. Review authorization, idempotency, recovery and artifact integrity separately from creative quality.

By submitting a contribution you agree to license it under Apache-2.0. Do not contribute code or assets you lack permission to license.
